# Как добавлять и обновлять игры

Этот файл — контракт между тобой и ассистентом. Здесь описано, что
присылать в промпте, откуда берутся картинки и ссылки, по каким
правилам из твоих правил прохождения рождаются цели и как присылать
отчёты после прохождения.

---

## 1. Что писать в промпте

Минимум — название и статус:

> Добавь Baldur's Gate 3, статус «в процессе», PC, 2023, сыграно 40 часов.

Если у тебя есть **свои правила комплишена** — присылай их, и цели будут
собраны строго по ним:

> Мои правила для BG3: обязательно все три акта, все компаньоны
> завербованы, романтическая линия доведена до конца, Хонор-режим
> не обязателен. Платина не нужна, достижения не считаю.

### Полезно добавить

| Что | Зачем |
|-----|-------|
| платформа, год, разработчик | показываются в шапке и на карточке |
| часы | идут в общую статистику |
| оценка 1–10 | считается средняя по коллекции |
| даты начала/конца | показываются на странице игры |
| 2–3 тега | показываются на карточке |
| причина дропа | отдельный блок на странице, если статус `dropped` |
| пожелания по дизайну | «сделай мрачно», «хочу неон», «как в игре» |

## 2. Статусы

| id | Подпись | Цвет |
|----|---------|------|
| `completed`   | Пройдено   | зелёный `#3ddc97` |
| `in-progress` | В процессе | янтарный `#ffb347` |
| `on-hold`     | Отложено   | фиолетовый `#b48cff` |
| `planned`     | В планах   | синий `#6aa6ff` |
| `dropped`     | Дропнуто   | красный `#ff5f6d` |

Нужен новый статус — скажи, он добавляется в `STATUSES`
в [`assets/js/core.js`](../assets/js/core.js), и дальше всё
(фильтры, легенда, статистика) подхватывается само.

## 3. Картинки

Логика живёт в `core.js → art()`. Три независимых пути, в порядке
приоритета.

### Путь 1 — игра есть в Steam

Достаточно указать App ID:

```js
steam: 1245620,
```

Steam отдаёт по нему предсказуемый набор без всяких ключей:

| Что | Где используется |
|-----|------------------|
| `header.jpg` 460×215 | баннер карточки на главной |
| `library_hero.jpg` 1920×620 | широкий кадр в шапке страницы |
| `library_600x900.jpg` | портретная обложка (про запас) |
| `logo.png` **с прозрачным фоном** | заменяет текстовый заголовок |

App ID виден в адресе страницы магазина:
`store.steampowered.com/app/`**`1245620`**`/`

### Путь 2 — игры в Steam нет

Консольные эксклюзивы, эмуляция, итчио, что угодно. Указываешь
картинки руками:

```js
art: {
  hero:   'assets/img/games/fire-emblem/hero.jpg',
  banner: 'assets/img/games/fire-emblem/banner.jpg',
  logo:   'assets/img/games/fire-emblem/logo.png',
},
```

- **Локальные пути** пишутся от корня сайта (`assets/img/...`) — префикс
  подставляется сам, поэтому одинаково работает и на главной, и на
  странице игры, и на GitHub Pages в подпапке.
- **Внешние ссылки** (`https://...`) вставляются как есть.
- Можно задать только часть — остальное возьмётся из Steam, если задан
  App ID, или отрисуется процедурно.

Чтобы добавить файлы: кидай картинки в `assets/img/games/<slug>/`
или просто пришли ссылки в промпте.

### Путь 3 — картинок нет вообще

Это **нормальный, а не аварийный** режим. Карточка рисует градиент из
акцентных цветов игры с крупной монограммой, а страница строит
процедурную графику. Пример — `fire-emblem-fortunes-weave`: у неё нет ни
одной картинки, и вся графика нарисована в SVG и на канвасе.

Если баннер указан, но не загрузился, он молча убирается и под ним
остаётся процедурный арт — сайт не ломается.

## 4. Ссылки

### Ссылки игры

Показываются в шапке страницы:

```js
links: [
  { kind: 'wiki', label: 'Fextralife', url: 'https://...' },
],
```

`kind` — `store`, `wiki`, `guide`, `video` или `other`; по нему страница
может красить ссылки по-разному. **Ссылка на Steam добавляется
автоматически**, если задан App ID, — руками её прописывать не нужно.

### Ссылки у целей

У любой цели может быть ссылка на вики, гайд или страницу босса:

```js
{ id: 'er-optional', title: 'Закрыть всех опциональных боссов', done: true,
  link: 'https://eldenring.wiki.fextralife.com/Malenia+Blade+of+Miquella' },
```

Иконка книги появляется справа в строке при наведении и открывает ссылку
в новой вкладке.

**Все ссылки проверяются перед тем, как попасть в файл.** Если страница
отдаёт 404, ссылка не добавляется — лучше без неё, чем битая.

## 5. Схема данных

Игры живут в [`data/games.js`](../data/games.js). Это обычный JS-файл,
а не JSON, — чтобы сайт работал и по http, и двойным кликом по
`index.html`.

```js
{
  slug: 'baldurs-gate-3',     // латиницей, через дефис = имя папки и URL
  title: "Baldur's Gate 3",
  status: 'in-progress',

  platform: 'PC',
  year: 2023,
  developer: 'Larian Studios',

  steam: 1086940,             // если игра есть в Steam
  art: { hero: '…' },         // если нет или хочется своё

  accent: '#c0392b',          // основной цвет игры
  accentAlt: '#8e44ad',       // дополнительный, для градиентов

  hours: 40,
  rating: 10,                 // 1–10, или null
  started: '2026-05-01',      // YYYY-MM-DD, или null
  finished: null,

  droppedAt: null,            // только для status: 'dropped'
  droppedReason: null,

  tags: ['RPG', 'D&D', 'Пошаговые бои'],
  verdict: 'Короткая личная оценка — выводится на странице игры.',

  links: [ … ],
  goals: [ … ],
}
```

### Цель

```js
{
  id: 'bg3-act1',            // уникален в пределах игры
  group: 'Сюжет',            // заголовок секции в чеклисте
  title: 'Пройти первый акт',
  done: false,
  note: 'Необязательное уточнение мелким шрифтом',
  optional: true,            // «бонус»: не влияет на процент
  link: 'https://…',         // гайд или страница босса
}
```

**Как считается прогресс.** Процент = закрытые обязательные цели делить
на все обязательные. Цели с `optional: true` в процент не входят и
показываются с меткой «бонус» — это челленджи вроде «пройти без
смертей», которые не должны мешать считать игру закрытой.

Игра получает печать 100% на карточке, когда выполнены все обязательные
цели.

## 6. Как из правил получаются цели

1. **Каждое отдельное проверяемое условие — одна цель.**
   «Все компаньоны и все их квесты» → две цели, а не одна:
   их можно закрыть в разное время.

2. **Цели группируются** по смыслу: Сюжет, Боссы, Карта, Сбор, NPC,
   DLC, Прокачка, Мета, Челлендж.

3. **Формулировки в твоих словах.** Если в правилах сказано «добить всех
   архидемонов» — так и будет записано, без причёсывания под энциклопедию.

4. **«Желательно», «если получится», «не обязательно»** → `optional: true`.

5. **Числа уходят в `note`**, а не в заголовок: «Собрать все амулеты»
   + `note: '45 штук'`.

6. **Спорные места выносятся вопросом**, а не угадываются. Если из правил
   неясно, считается ли DLC частью прохождения, ты получишь прямой вопрос
   до того, как игра будет добавлена.

## 7. Отчёт о прохождении

Когда закончил игру — пришли отчёт в любом виде, хоть списком, хоть
текстом. Разбирается и то и другое:

> Закончил Cyberpunk. 94 часа, оценка 9. Закрыл всё кроме Very Hard
> и машин у Autofixer. Phantom Liberty прошёл на обе концовки.
> Финальная дата — 12 октября.

Из такого отчёта обновляется:

- `status` → `completed`, `finished` → дата
- `hours`, `rating`
- `done: true` у перечисленных целей
- `verdict` — если ты написал впечатление

Что происходит дальше:

- **Неоднозначные цели не отмечаются молча.** Если из отчёта не ясно,
  закрыта ли цель, придёт вопрос.
- **Новые цели можно добавлять задним числом.** «Оказалось, там ещё
  секретная концовка» — добавится и отметится.
- Статистика на главной пересчитается сама — руками ничего править не
  нужно.

Можно и короче:

> Hollow Knight — закрыл амулеты и журнал охотника, 34 часа.

Статус переведётся в «в процессе», часы обновятся, две цели закроются.

### Отметки, сделанные прямо на сайте

Галочки на странице игры сохраняются в `localStorage` браузера и
**не меняют** `data/games.js`. Чтобы зафиксировать их в репозитории:

1. Нажми **«Скопировать состояние»** на странице игры.
2. Вставь скопированное в промпт.
3. Отметки переедут в `data/games.js` и попадут в коммит.

Кнопка **«Сбросить»** убирает локальные отметки этой игры и возвращает
состояние из файла.

## 8. Дизайн страницы игры

У каждой игры своя папка `games/<slug>/` из трёх файлов:

```
games/<slug>/
├── index.html   разметка под конкретную игру
├── style.css    полностью свой скин
└── fx.js        свои визуальные эффекты
```

Общими остаются только `assets/css/base.css` (каркас чеклиста) и
`assets/js/game.js` (логика целей и прогресса). Всё остальное — цвета,
шрифты, сетка, анимации, работа с артом — пишется под игру с нуля.

Что уже есть, чтобы было видно разброс:

| Игра | Решение |
|------|---------|
| Elden Ring | золотой свиток, кадр утоплен в сепию, угли, ромбы-руны |
| Cyberpunk 2077 | HUD-терминал, кадр как «видеопоток», глитч, цифровой дождь |
| Hollow Knight | кадр тонет в синей глубине, споры, фонарь за курсором |
| Starfield | приборная панель, кадр как архивный снимок, штамп ABORTED |
| Fire Emblem | **светлая** страница: тканый гобелен, SVG-герб, нити судьбы |

Fire Emblem сделана светлой намеренно: пятая тёмная страница была бы
повторением. Рекомендация на будущее — каждая новая игра должна
отличаться не только палитрой, но и композицией, типографикой и
характером движения.

### Что должно быть в разметке

Движок ищет эти атрибуты — без них страница не оживёт:

| Атрибут | Что делает |
|---------|-----------|
| `data-game="slug"` на `<body>` | указывает, какую игру рисовать |
| `[data-goals]` | контейнер, куда вставляется чеклист |
| `[data-ring]` | контейнер для SVG-кольца прогресса |
| `[data-logo]` | сюда вставляется логотип, если загрузился |
| `[data-links]` | сюда вставляются ссылки игры |
| `[data-progress-pct]` | число процентов |
| `[data-progress-done]` / `[data-progress-total]` | счётчик целей |
| `[data-progress-bar]` | элемент, которому ставится `width` |
| `[data-export]` / `[data-reset]` | кнопки работы с отметками |
| `[data-local-badge]` | индикатор несохранённых отметок |

### Что движок отдаёт странице

CSS-переменные на `:root` — страница распоряжается ими как хочет:

```
--accent, --accent-rgb, --accent-alt, --accent-alt-rgb
--art-hero, --art-banner, --art-capsule, --art-logo
```

Классы на `<body>`:

```
has-art      есть кадр для шапки
has-logo     логотип загрузился (обычно текстовый заголовок прячут)
logo-failed  логотип не загрузился
is-perfect   все обязательные цели закрыты
is-absolute  закрыты даже бонусные
```

### Классы чеклиста

```
.g-group  .g-group__head  .g-group__name  .g-group__count
.g-list   .g-goal  .g-goal.is-done  .g-goal.is-optional
.g-goal__toggle  .g-goal__box  .g-goal__title
.g-goal__note    .g-goal__flag  .g-goal__link
.g-link                              ← ссылки игры
```

Важно: `.g-goal__link` лежит **снаружи** `.g-goal__toggle` — `<a>` внутри
`<button>` невалиден и ломает клик.

### Событие для своих эффектов

```js
document.addEventListener('completionist:toggle', function (e) {
  e.detail.game;      // объект игры
  e.detail.goal;      // какая цель
  e.detail.done;      // true, если закрыли
  e.detail.progress;  // пересчитанный прогресс
  e.detail.element;   // <li> этой цели
});
```

Все пять страниц используют его по-разному: Elden Ring пускает золотую
искру, Cyberpunk ломает развёртку, Hollow Knight расходится волной
света, Starfield даёт импульс телеметрии, Fire Emblem прошивает стежок.

## 9. Примеры промптов

**Новая игра с правилами:**

> Добавь Sekiro, статус «в процессе», 30 часов, PC.
> Правила: все концовки, все боссы включая опциональных,
> все протезы прокачаны. Без Demon Bell и без чарметра —
> это бонус. Дизайн: японская графика, тушь, красный акцент.

**Игра не из Steam:**

> Добавь Metroid Prime 4, Switch, в планах.
> Картинки возьми отсюда: <ссылка на баннер>, <ссылка на лого>.

**Отчёт о прохождении:**

> Закончил Elden Ring на 100%, 143 часа, оценка 10.
> Последним закрыл платину 18 января.

**Правка целей:**

> В Hollow Knight убери цель про Steel Soul, добавь
> «Пройти Path of Pain» в группу Челлендж.

**Переделать дизайн:**

> Страница Starfield слишком холодная, сделай теплее
> и добавь эффект помех на заголовке.
